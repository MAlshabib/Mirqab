# مراقب — نظام الكشف الفوري عن التهديدات الجوية ودمج بيانات المستشعرات

> **Mirqab** — مراقب الأجواء في الوقت الفعلي

مراقب منصة شاملة للوعي الميداني ورصد الأجواء والإنذار المبكر. يدمج النظام بيانات متعددة المصادر — رؤية حاسوبية وتصنيف صوتي — من وحدات ميدانية موزعة، ويصنع صورة تهديد موحدة تُبث مباشرةً إلى لوحة قيادة مركز العمليات. صُمّم النظام للكشف عن التهديدات الجوية المنخفضة الارتفاع (الطائرات المسيّرة والطائرات التقليدية) مع دعم بروتوكولات تسليم القيادة والسيطرة وفق معايير حلف الناتو.

## نماذج الذكاء الاصطناعي والتعلم الآلي

### نموذج الرؤية — YOLOv8m (مُدرَّب خصيصاً)

يعتمد مراقب على نموذج **YOLOv8m** (You Only Look Once، الإصدار 8، الحجم المتوسط) المُدرَّب خصيصاً بوصفه محرك الكشف البصري الأساسي. دُرِّب النموذج على مجموعة بيانات جوية مُنظَّمة تحتوي على صور للطائرات المدنية والعسكرية والمسيّرات والطيور.

**تفاصيل النموذج:**

| الخاصية | القيمة |
|---------|--------|
| المعمارية الأساسية | YOLOv8m (Ultralytics) |
| المهمة | الكشف عن الأجسام |
| المدخل | إطارات JPEG (أي دقة، تُعاد أبعادها داخلياً) |
| الفئات الخرجية | `uav_threat`، `aircraft`، `bird` |
| عتبة الثقة | 0.85 (قابل للضبط) |
| زمن التبريد بين الكشوفات | 2 ثانية لكل فئة (يمنع الإغراق) |
| المتتبع | BoTSORT (تتبع متعدد الأجسام عبر SciPy) |
| مكتبة الاستدلال | `ultralytics` |
| أوزان النموذج | `model/model_workspace/models/best_model.pt` |

**تصنيف مستوى الخطورة:**

| الفئة المكتشفة | الخطورة |
|--------------|---------|
| `uav_threat` | **عالية** |
| `aircraft` | **متوسطة** |
| `bird` | **منخفضة** |

**خط أنابيب إعداد بيانات التدريب:**

يتولى خط أنابيب التنظيم (في `model/model_workspace/`) المهام التالية:
- تجميع أكثر من 54,000 صورة من مجموعات بيانات مفتوحة للمسيّرات والطائرات العسكرية والمدنية
- توحيد التسميات عبر صيغ التوصيف المختلفة
- الكشف عن التكرارات باستخدام التجزئة الإدراكية (Perceptual Hash)
- فحوصات الجودة (الحد الأدنى للدقة، كثافة التسميات)
- التصدير بصيغة YOLO مع تقسيم بيانات التدريب والتحقق والاختبار

ينتج الخط مجموعة بيانات نظيفة تستهدف أربع فئات أساسية: `civilian_aircraft`، `military_aircraft`، `uav`، و`background`، تُعيَّن لاحقاً إلى الفئات التشغيلية الثلاث.

**سير العمل في خط الأنابيب:**

```
الكاميرا تلتقط إطار JPEG
        │
        ▼
frame_processor.process_frame()
        │
        ▼
استدلال YOLOv8m ← مربعات تحديد + فئة + ثقة
        │
        ▼
متتبع BoTSORT يُسنّد معرّفات ثابتة للأجسام
        │
        ▼
تصفية بثقة ≥ 0.85 + زمن التبريد لكل فئة
        │
        ▼
حفظ لقطة مُوصَّفة ← /static/detections/{uuid}.jpg
        │
        ▼
إرسال الكشف إلى محرك الدمج
```

### نموذج الصوت — MirqabCNN (مخصص)

**MirqabCNN** شبكة عصبية التفافية مبنية من الصفر للتصنيف الصوتي للبصمات الجوية من إدخال الميكروفون. دُرِّبت على تمثيلات Mel-Spectrogram لضجيج مراوح المسيّرات ومحركات الطائرات.

**معمارية النموذج:**

```
المدخل: Mel-spectrogram (1 × 128 × T) — صوت أحادي بتردد 16 كيلوهرتز
         │
         ▼
ConvBlock 1: Conv2d(1→32, 3×3, bias=False) → BatchNorm2d → ReLU → MaxPool2d(2,2)
         │
         ▼
ConvBlock 2: Conv2d(32→64, 3×3, bias=False) → BatchNorm2d → ReLU → MaxPool2d(2,2)
         │
         ▼
ConvBlock 3: Conv2d(64→128, 3×3, bias=False) → BatchNorm2d → ReLU → MaxPool2d(2,2)
         │
         ▼
ConvBlock 4: Conv2d(128→256, 3×3, bias=False) → BatchNorm2d → ReLU → MaxPool2d(2,2)
         │
         ▼
Global Average Pooling → تسطيح (256 بُعد)
         │
         ▼
Dropout → Linear(256 → 3)
         │
         ▼
المخرج: softmax على [uav, aircraft, background]
```

**تفاصيل معالجة الصوت:**

| الخاصية | القيمة |
|---------|--------|
| معدل أخذ العينات | 16,000 هرتز (إعادة أخذ عينات تلقائية) |
| حجم النافذة | 1.0 ثانية |
| الخطوة | 0.5 ثانية (تداخل 50%) |
| حجم FFT | 1024 |
| طول القفزة | 512 |
| نطاقات Mel | 128 |
| التطبيع | درجة Z لكل طيف (mean=0, std=1) |
| الفئات الخرجية | `uav`، `aircraft`، `background` |
| عتبة الثقة | 0.70 (قابل للضبط) |
| زمن التبريد | 3 ثوانٍ لكل فئة |
| أوزان النموذج | `model/audio_workspace/models/best_model.pth` |
| الإطار | PyTorch + torchaudio |

**سير العمل في خط الأنابيب:**

```
الميكروفون يلتقط صوت PCM (16 كيلوهرتز، أحادي)
        │
        ▼
ذاكرة حلقية تجمع نوافذ بمقدار ثانية واحدة بخطوة 0.5 ثانية
        │
        ▼
حساب Mel-spectrogram ← موتّر (1, 128, ~96)
        │
        ▼
تطبيع Z-score
        │
        ▼
استدلال MirqabCNN ← احتمالات الفئات
        │
        ▼
تصفية بثقة ≥ 0.70، تجاهل "background"
تطبيق زمن التبريد (3 ثوانٍ)
        │
        ▼
إرسال الكشف الصوتي إلى محرك الدمج
```

**خط أنابيب التدريب:**

يستخدم خط أنابيب تدريب الصوت (في `model/audio_workspace/`) ما يلي:
- **Librosa** لاستخراج الميزات والتعزيز
- **torchaudio** لحساب الطيف في الوقت الفعلي
- **scikit-learn** للتقسيم الطبقي لبيانات التدريب والتحقق
- التعزيز: تمديد الزمن، تحريك الطبقة، ضجيج غاوسي
- إطار التدريب: **PyTorch** مع محسّن AdamW وجدول تعلّم Cosine

### محرك دمج المستشعرات

محرك الدمج (`back-end/app/fusion.py`) هو مكوّن اتخاذ القرار الأساسي. هدفه **خفض الإيجابيات الكاذبة** عبر اشتراط تأكيد كشف من نمطين مستشعريين مستقلين قبل إصدار تنبيه التهديد.

**معادلة الدمج:**

```
درجة الدمج = (0.6 × ثقة الرؤية) + (0.4 × ثقة الصوت)
```

**قواعد اتخاذ القرار:**

| درجة الدمج | الإجراء |
|-----------|---------|
| ≥ 0.80 | إصدار تنبيه التهديد + حفظ في قاعدة البيانات + بث لجميع عملاء مركز العمليات |
| < 0.80 | تجاهل (ثقة غير كافية) |

**استراتيجية المطابقة:**

يُطابق المحرك الكشوفات البصرية والصوتية ضمن **نافذة زمنية مدتها 15 ثانية**:

1. **مطابقة نفس الفئة** (مفضّلة): رؤية `uav` + صوت `uav` ← دمج `uav`
2. **احتياطي العبور بين الفئات**: رؤية `aircraft` + صوت `uav` ← دمج `aircraft` (فئة الرؤية تسبق)

**توحيد الفئات:**

| المصدر | الفئة الأصلية | فئة الدمج |
|--------|-------------|----------|
| رؤية | `uav_threat` | `uav` |
| رؤية | `aircraft` | `aircraft` |
| رؤية | `bird` | *(محذوف — غير ذي صلة بالتهديد)* |
| صوت | `uav` | `uav` |
| صوت | `aircraft` | `aircraft` |
| صوت | `background` | *(محذوف)* |

**ضوابط إضافية:**
- **تبريد الدمج**: 10 ثوانٍ بين تنبيهات نفس الفئة لكل وحدة (يمنع إغراق التنبيهات عند التهديدات المستدامة)
- **المطابقة المكانية**: سياسة الوحدة الأقرب عبر مسافة هافرساين عند نشر وحدات ميدانية متعددة
- **تنظيف المخزن المؤقت المعلّق**: تُهمل الكشوفات غير المطابقة بعد 15 ثانية

### المساعد الذكي RAG — Qwen2.5 وتضمينات Qwen3

يتضمن مراقب مساعداً ذكياً يعمل بتقنية RAG يجيب على أسئلة المشغّلين حول المشهد التهديدي الحالي وصحة المستشعرات وسجل الحوادث والإجراءات التشغيلية. يعمل **محلياً تماماً** عبر Ollama — دون أي استدعاءات لخدمات سحابية خارجية.

**النماذج المستخدمة:**

| المكوّن | النموذج | الغرض |
|---------|---------|-------|
| نموذج اللغة (LLM) | `qwen2.5:14b-instruct` | توليد الإجابات (عربي + إنجليزي) |
| التضمينات | `dengcao/Qwen3-Embedding-0.6B:Q8_0` | البحث الدلالي في الوثائق |

**المعمارية:**

```
استعلام المشغّل (عربي أو إنجليزي)
        │
        ▼
حارس النطاق — يحجب استعلامات الاستهداف التكتيكي / الأسلحة
        │
        ▼
توجيه إلى: استرجاع RAG  أو  استعلام تحليلي من DB
        │                          │
   بحث متجهي                استعلام SQLite
   أفضل 5 مقاطع            (إحصاءات التهديد،
   من قاعدة المعرفة          صحة المستشعرات،
   (الإجراءات، الأدلة)        الإحصاء اليومي)
        │                          │
        └──────────┬───────────────┘
                   │
                   ▼
        Qwen2.5:14b-instruct
        (درجة حرارة = 0.1 للدقة)
        البرومبت الجذري يفرض:
          - نطاق مراقب فقط
          - لا إحصاءات مخترعة
          - ثنائي اللغة (كشف تلقائي)
          - إسناد المصادر
                   │
                   ▼
        الإجابة + إسناد المصادر ← الواجهة
```

**قيود النطاق (البرومبت الجذري):**

يقتصر المساعد على:
- ملخصات تنبيهات مراقب وإحصاءات التهديدات
- حالة وحدات المستشعرات وصحتها
- تحليلات لوحة التحكم وتقارير الحوادث
- استكشاف الأخطاء التشغيلية وإصلاحها

يرفض المساعد صراحةً:
- تقديم نصائح الاستهداف التكتيكي
- توجيهات التحكم بالنيران
- المساعدة في تعليمات نشر الأسلحة

## بروتوكول WebSocket

### `/ws/hq` — بث مركز العمليات

جميع عملاء لوحة التحكم المتصلين يستقبلون أحداث التهديد وتغيرات حالة الوحدات في الوقت الفعلي.

**أنواع الرسائل الواردة:**

```json
{
  "type": "detection",
  "unit_id": "vision-01",
  "unit_type": "vision",
  "label": "uav_threat",
  "confidence": 0.94,
  "severity": "high",
  "lat": 24.6877,
  "lng": 46.7219,
  "timestamp": "2025-10-15T09:32:17Z",
  "source": "fusion",
  "frame_url": "/static/detections/abc123.jpg",
  "track_id": "TRK-00042"
}
```

```json
{
  "type": "unit_status",
  "unit_id": "acoustic-01",
  "status": "online",
  "last_seen": "2025-10-15T09:32:10Z"
}
```

### `/ws/unit/{unit_id}/feed` — تغذية الفيديو من الوحدة الميدانية (وارد)

ترسل الكاميرات الميدانية إطارات JPEG كرسائل WebSocket ثنائية إلى هذه النقطة. يفكّ الخادم الترميز، ويشغّل استدلال YOLO، ويمرر الإطارات للمشاهدين.

### `/ws/unit/{unit_id}/view` — مشاهد فيديو مركز العمليات (صادر)

يشترك عملاء مركز العمليات في استقبال إطارات JPEG مُوصَّفة من وحدة ميدانية محددة. تُحوَّل الإطارات كرسائل ثنائية بمعدل التقاط الكاميرا.

## تكامل C2 (CoT و ASTERIX)

يدعم مراقب تصدير المسارات المؤكدة إلى أنظمة C2 الخارجية عبر صيغتين قياسيتين.

### Cursor-on-Target (CoT) XML

صيغة متوافقة مع TAK لأدوات الوعي المشترك (ATAK، WinTAK، iTAK):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<event uid="TRK-00042" type="a-h-A-M-F-U" time="2025-10-15T09:32:17Z"
       start="2025-10-15T09:30:00Z" stale="2025-10-15T09:47:17Z" how="m-r">
  <point lat="24.6877" lon="46.7219" hae="250.0" ce="50.0" le="30.0"/>
  <detail>
    <track speed="18.5" course="215.0"/>
    <remarks>UAV threat | Fused confidence: 0.91 | Vision: 0.94 | Acoustic: 0.87</remarks>
  </detail>
</event>
```

### ASTERIX CAT062 JSON

صيغة معيار حلف الناتو لأنظمة دمج بيانات الرادار والمستشعرات:

```json
{
  "category": 62,
  "trackNumber": "TRK-00042",
  "positionWGS84": { "latitude": 24.6877, "longitude": 46.7219, "altitude_m": 250.0 },
  "groundSpeed": 18.5,
  "trackAngle": 215.0,
  "verticalRate": -1.2,
  "confidence": 0.91,
  "threatLevel": "high",
  "objectType": "UAV",
  "status": "confirmed",
  "timestamp": "2025-10-15T09:32:17Z"
}
```

```sql
-- وحدات المستشعرات (الكاميرات والميكروفونات)

);

CREATE TABLE detection_events (
    id            TEXT PRIMARY KEY,
    unit_id       TEXT,
    unit_type     TEXT,
    event_type    TEXT,           -- "detection"
    label         TEXT,           -- "uav" | "aircraft" | "uav_threat" | ...
    confidence    FLOAT,
    severity      TEXT,           -- "low" | "medium" | "high"
    lat           FLOAT,
    lng           FLOAT,
    timestamp     TIMESTAMP,
    source        TEXT,           -- "model" | "fusion" | "simulator" | "unit_web_demo"
    frame_id      TEXT,
    frame_url     TEXT,           -- /static/detections/{uuid}.jpg
    bbox_json     TEXT,           -- {"x1", "y1", "x2", "y2"}
    metadata_json TEXT
);

-- المسارات التكتيكية التي تديرها بوابة C2
CREATE TABLE tactical_tracks (
    track_id              TEXT PRIMARY KEY,
    object_type           TEXT,   -- "UAV" | "AIRCRAFT" | "UNKNOWN"
    threat_level          TEXT,   -- "low" | "medium" | "high" | "critical"
    status                TEXT,   -- "new" | "tracking" | "confirmed" | "lost"
    recommended_action    TEXT,
    lat                   FLOAT,
    lon                   FLOAT,
    alt_m                 FLOAT,
    speed_mps             FLOAT,
    heading_deg           FLOAT,
    vertical_rate_mps     FLOAT,
    confidence_vision     FLOAT,
    confidence_acoustic   FLOAT,
    confidence_fused      FLOAT,
    horizontal_error_m    FLOAT,
    vertical_error_m      FLOAT,
    node_id               TEXT,
    source_unit_type      TEXT,
    sensor_ids_json       TEXT,   -- مصفوفة JSON لمعرّفات المستشعرات المساهِمة
    created_at            TIMESTAMP,
    updated_at            TIMESTAMP,
    last_seen_at          TIMESTAMP,
    detection_event_id    TEXT,
    frame_url             TEXT
);
```

## خطوط التدريب

```bash
# تشغيل التنظيم
cd model/model_workspace

# تنظيم وتصدير مجموعة البيانات
python curate_dataset.py   # توحيد + إزالة التكرارات + فحص الجودة

# التدريب (يتطلب GPU)
yolo train model=yolov8m.pt data=dataset.yaml epochs=100 imgsz=640
```

### تدريب الصوت (`model/audio_workspace/`)

يُدرّب خط الأنابيب الصوتي نموذج MirqabCNN على طيف Mel:

```bash
cd model/audio_workspace
pip install -r requirements.txt

# استخراج الميزات من ملفات الصوت الأصلية
python extract_features.py --input raw_audio/ --output spectrograms/

# تدريب MirqabCNN
python train.py --data spectrograms/ --epochs 50 --lr 1e-3

# التقييم
python evaluate.py --model models/best_model.pth --test spectrograms/test/
```

```
numpy, scipy, librosa, soundfile, pandas, pyarrow, tqdm,
```

## لقطات الشاشة والواجهة

### لوحة التحكم الرئيسية

تُوفّر العرض الأساسي للمشغّل: خريطة تهديدات فورية، لوحة تنبيهات مباشرة، ولوحة حالة المستشعرات. التهديدات مُرمَّزة بالألوان حسب النوع (مسيّرة = أخضر زمردي، طائرة = أزرق) والخطورة. يمكن للمشغّلين النقر على أي علامة تهديد لعرض لقطة الكشف من الكاميرا الميدانية.

### كونسول C2 التكتيكي

تعرض شاشة C2 جميع المسارات التكتيكية النشطة مع حالتها الحركية (الموضع، السرعة، الاتجاه، الارتفاع). كل مسار يعرض درجات ثقة الرؤية/الصوت/الدمج ويمكن تصديره بصيغة CoT XML أو ASTERIX CAT062 JSON، أو وضع علامة عليه للتسليم للرادار.

### المساعد الذكي للمشغّلين

واجهة محادثة تدعم العربية والإنجليزية. يمكن للمشغّلين طرح أسئلة بلغة طبيعية حول المشهد التهديدي ("ما أعلى كشوفات ثقة اليوم؟"، "أيّ وحدات المستشعرات غير متصلة؟"). يستشهد المساعد بمصادره ويرفض الاستعلامات التكتيكية خارج النطاق.

### وضع المحاكاة

بدّل المحاكي من الشريط الجانبي لحقن كشوفات اصطناعية دون أجهزة فيزيائية — مثالي لتدريب المشغّلين واختبار الواجهة والعروض التوضيحية.
